# منظومة تتبع المستندات الداخلية (Flask MVP)

تطبيق Flask يطبّق وثيقة متطلبات النظام (SRS) لمنظومة تتبع المستندات الداخلية:
رفع ملف Word/PDF → تحديد المُرسَل إليه → إصدار وأرشفة تلقائية → توليد QR وPDF → تحقق عام بدون تسجيل دخول.

> ملاحظة: الوثيقة الأصلية صُممت على Firebase (Auth/Firestore/Storage). تم بناء هذا الإصدار بـ
> **Flask + SQLAlchemy (SQLite) + Flask-Login** كبديل قائم على خادم واحد، مع الحفاظ على نفس
> نموذج البيانات والمنطق الوظيفي (FR-1 إلى FR-8). يمكن استبدال SQLite بـ PostgreSQL/MySQL
> بتغيير `DATABASE_URL` فقط دون تعديل الكود.

## المتطلبات
- Python 3.10+ 
- (اختياري) بيئة افتراضية venv

## التثبيت والتشغيل

```bash
# 1) إنشاء بيئة افتراضية
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate

# 2) تثبيت الحزم
pip install -r requirements.txt

# 3) تهيئة قاعدة البيانات
export FLASK_APP=run.py         # على ويندوز (PowerShell): $env:FLASK_APP="run.py"
flask init-db

# 4) (اختياري) إضافة بيانات وحسابات تجريبية
flask seed

# 5) تشغيل الخادم
flask run
# أو: python run.py
```

الآن افتح المتصفح على: **http://127.0.0.1:5000**

## المتطلبات الوظيفية المُنفَّذة في هذا الـ MVP

- **FR-1** إدارة المستخدمين: تسجيل دخول، 4 أدوار، كل مستخدم بقسم واحد، تغيير كلمة السر
- **FR-2** رفع المستند وإصداره: نموذج مختصر (نوع، عنوان، مُرسَل إليه)، زر إصدار لا يُفعَّل إلا عند اكتمال البيانات، عملية إصدار واحدة (رقم + أرشفة + QR + PDF)
- **FR-3** رفع وتخزين الملفات: .docx/.doc/.pdf، حد 10MB، تنظيم حسب القسم/المستند، معاينة PDF
- **FR-4** سجل تدقيق لكل عملية (إصدار، عرض من الأرشيف، تحقق عام)
- **FR-5** بحث وفلترة: نص، نوع، قسم، تاريخ من-إلى، ترتيب
- **FR-6** تحقق عبر QR: صفحة عامة بدون تسجيل دخول تعرض بيانات المستند + الملف المؤرشف نفسه
- **FR-7** أرشفة تلقائية فورية دون مرحلة مراجعة وسيطة (كما حُدِّد في القرار المفتوح رقم 1)
- **FR-8** لوحة تحكم: إحصائيات، رسم بياني بسيط حسب القسم، أحدث المستندات

**خارج نطاق هذا الإصدار** (كما هو محدد في الوثيقة تحت "خارج النطاق" و FR-9): التوقيع الإلكتروني
المعتمد قانونيًا، تكامل البريد الإلكتروني الرسمي، توليد مستندات Word من قوالب (docxtemplater)،
تطبيق موبايل مستقل، تصدير CSV (FR-5.4).

## قرارات مفتوحة من الوثيقة تحتاج قرارك قبل الإنتاج

راجع قسم "قرارات مفتوحة" في الوثيقة الأصلية:

1. هل PDF الإصدار صفحة غلاف منفصلة + رابط للملف الأصلي، أم دمج فعلي لصفحة الغلاف مع محتوى
   الملف الأصلي؟ **(هذا الإصدار ينفّذ الخيار الأول: صفحة غلاف تحتوي QR + بيانات، والملف الأصلي
   متاح للتحميل من صفحة التفاصيل فقط، وليس من صفحة التحقق العامة — فقط PDF الغلاف متاح علنًا)**
2. بما أن صفحة التحقق العامة تعرض ملف PDF الغلاف لأي حامل للرابط (FR-6.4): هل يلزم استثناء
   أنواع مستندات حساسة معيّنة من العرض العام، أو إضافة صلاحية انتهاء للرابط؟ لم يُنفَّذ أي تحكم
   إضافي في هذا الـ MVP.

## ملاحظات تقنية

- **الترقيم التسلسلي**: يعتمد على جدول `counters` مع معاملة قاعدة بيانات واحدة (transaction) لكل
  عملية إصدار لتفادي التكرار عند الاستخدام المتزامن، كما نبّهت الوثيقة في قسم "المخاطر".
- **التبديل لـ PostgreSQL/MySQL في الإنتاج**: غيّر `DATABASE_URL` في متغيرات البيئة، مثال:
  `postgresql://user:pass@localhost/docsys`. لا حاجة لتعديل الكود بفضل SQLAlchemy.
- **الأمان**: هذا MVP يستخدم `SECRET_KEY` افتراضي للتطوير فقط — **يجب تغييره** عبر متغير بيئة
  `SECRET_KEY` قبل أي نشر حقيقي. كذلك يُنصح بتفعيل HTTPS إجباريًا (NFR-1).
- **خط PDF العربي**: يستخدم خط Noto Naskh Arabic (Google Fonts، رخصة OFL) المرفق في
  `app/static/fonts/`.
