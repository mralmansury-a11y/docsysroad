# منظومة تتبع المستندات الداخلية

تطبيق Flask لتتبع المستندات الداخلية: رفع ملف (Word/PDF) → تحديد المُرسَل إليه → إصدار
وأرشفة تلقائية → توليد رقم مرجعي ورمز QR → تحقق عام بدون تسجيل دخول.

مبني بـ **Flask + SQLAlchemy (SQLite) + Flask-Login**. يمكن استبدال SQLite بـ
PostgreSQL/MySQL عبر متغير البيئة `DATABASE_URL` دون تعديل الكود.

## المتطلبات

- Python 3.10+
- خط Noto Naskh Arabic (مرفق في `app/static/fonts/`)
- صورة الورق الرسمي للجهة (مرفقة في `app/static/pdf_assets/letterhead.jpg`)

## التثبيت والتشغيل

```bash
python3 -m venv venv
source venv/bin/activate        # ويندوز: venv\Scripts\activate

pip install -r requirements.txt

export FLASK_APP=run.py         # ويندوز (PowerShell): $env:FLASK_APP="run.py"
flask init-db
flask seed                      # اختياري: بيانات وحسابات تجريبية

flask run                       # أو: python run.py
```

التطبيق: **http://127.0.0.1:5000**

## المتطلبات الوظيفية

- **إدارة المستخدمين**: تسجيل دخول، 4 أدوار (مدير نظام، رئيس قسم، موظف، أرشيف)، إدارة كاملة
  من لوحة الإدارة (Admin فقط)
- **رفع وإصدار المستند**: نموذج مختصر، عملية إصدار واحدة تشمل الترقيم والأرشفة والتوليد
- **الترقيم التسلسلي**: عبر جدول `counters` بمعاملة قاعدة بيانات واحدة لكل إصدار، لتفادي
  التكرار عند الاستخدام المتزامن
- **الأرشفة التلقائية**: فورية دون مرحلة مراجعة وسيطة
- **سجل تدقيق**: لكل عملية (إصدار، عرض من الأرشيف، تحقق عام)
- **بحث وفلترة**: نص، نوع، قسم، تاريخ، ترتيب، مع ترقيم صفحات
- **تحقق عام عبر QR**: صفحة بدون تسجيل دخول تعرض بيانات المستند وتتيح تحميل PDF الإصدار
- **لوحة تحكم**: إحصائيات ورسم بياني حسب القسم

## هوية الملفات الرسمية (QR والورق الرسمي)

| العملية | ملفات PDF | ملفات Word (.docx) |
|---|---|---|
| عند رفع الملف الأصلي | يُختم فورًا برمز QR والرقم المرجعي أعلى الصفحة الأولى فقط (بدون ورق رسمي) | يُحفَظ كما هو، بدون أي ختم |
| زر "تحميل الملف الأصلي مع الباركود" | تنزيل مباشر للأصل كما هو (QR موجود أصلًا منذ الرفع) | يُضاف QR والرقم عند الطلب في ترويسة الصفحة الأولى (بدون ورق رسمي) |
| PDF الإصدار (صفحة الغلاف) | يُولَّد دائمًا فوق الورق الرسمي الكامل + QR + بيانات المستند | — |

**ملاحظة**: المستندات المؤرشفة قبل اعتماد هذا السلوك لا تحمل QR في ملفها الأصلي؛ زر
"تحميل مع الباركود" سيُنزّلها دون QR لأنه لا يُجري أي معالجة إضافية على ملفات PDF.

## قرارات مفتوحة تحتاج اعتمادًا قبل الإنتاج

1. PDF الإصدار حاليًا صفحة غلاف منفصلة (QR + بيانات)، والملف الأصلي متاح للتحميل من صفحة
   التفاصيل فقط، وليس من صفحة التحقق العامة.
2. صفحة التحقق العامة متاحة لأي حامل رابط دون قيود إضافية (بدون استثناء أنواع حساسة أو
   صلاحية انتهاء).

## ملاحظات تقنية

- **الأمان**: `SECRET_KEY` الحالي مخصص للتطوير فقط — **يجب تغييره** عبر متغير بيئة قبل أي
  نشر حقيقي، مع تفعيل HTTPS إجباريًا.
- **`APP_DOMAIN`**: يُستخدم لبناء رابط التحقق داخل QR. يجب ضبطه على النطاق الفعلي للخادم
  في الإنتاج، وإلا ستُولَّد روابط QR تشير إلى `127.0.0.1`.
- **قاعدة البيانات**: التبديل لـ PostgreSQL/MySQL عبر `DATABASE_URL` فقط.
- **الخط العربي**: Noto Naskh Arabic (رخصة OFL)، مستخدم في جميع ملفات PDF المولَّدة.
